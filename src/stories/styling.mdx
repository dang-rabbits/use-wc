# Styling

Authoring CSS selectors can be complicated due to the inherint limitations of `part` and other Shadow DOM selectors. To overcome this there are plans to provide an opinionated theming layer built using CSS custom properties (aka, CSS variables). The custom property names will borrow concepts from semantic design token naming conventions. This approach will allow adopting teams to utilize their own design system core and alias tokens.

```css
/* your theme.css */
body.light-theme {
  --usewc-color-brand-primary: #00f;
  --usewc-color-secondary: #00f;
  --usewc-color-attention: #f00;
  --usewc-color-danger: #f00;
  --usewc-color-success: #f00;
  --usewc-color-info: #f00;
  --usewc-color-warning: #f00;
  --usewc-color-focus-ring: #00f;

  --usewc-color-input-background-static: #eaeaea;
  --usewc-color-input-background-focus: #fff;
  --usewc-color-input-background-hover: #fff;
  --usewc-color-input-background-valid: #fff;
  --usewc-color-input-background-invalid: #fff;
  --usewc-color-input-border-static: #ccc;
  --usewc-color-input-border-focus: #00f;
  --usewc-color-input-border-valid: #0f0;
  --usewc-color-input-border-invalid: #f00;
  --usewc-color-input-text-static: #333;
  --usewc-color-input-text-placeholder: #888;
  --usewc-color-input-trigger-static: #ccc;
  --usewc-color-input-trigger-hover: #ccc;
  --usewc-color-input-segment-static: #ccc;
  --usewc-color-input-segment-hover: #ccc;
  --usewc-color-input-segment-focus: #ccc;

  --usewc-color-selector-background-static: #fff;
  --usewc-color-selector-background-hover: #eaeaea;
  --usewc-color-selector-background-focus: #eaeaea;
  --usewc-color-selector-border-static: #ccc;
  --usewc-color-selector-border-hover: #ccc;
  --usewc-color-selector-border-focus: #ccc;

  --usewc-size-input-border: 1px;
  --usewc-size-button-border: 1px;
  --usewc-size-selector-border: 1px;
  --usewc-size-focus-ring: 2px;

  --usewc-space-input-padding-inline: 1rem;
  --usewc-space-input-padding-block: 0.5rem;
  --usewc-space-input-gap: 1rem;
  --usewc-space-input-focus-ring: 2px;
  --usewc-space-action-focus-ring: -1px;
  --usewc-space-selector-focus-ring: -1px;

  --usewc-effect-focus-ring-style: solid;
  --usewc-effect-input-border-radius: 0.25rem;
  --usewc-effect-action-button-border-radius: 0.25rem;
  --usewc-effect-selector-checkbox-border-radius: 0.25rem;
  --usewc-effect-selector-radio-border-radius: 0.25rem;
  --usewc-effect-selector-switch-border-radius: 0.25rem;
}

/* imported use-wc.css */
button {
  all: unset;
  display: inline-flex;
  align-items: center;
  border: var(--usewc-size-input-border) solid var(--usewc-color-input-border-static);
  padding: var(--usewc-space-input-padding-block) var(--usewc-space-input-padding-inline);
  gap: var(--usewc-space-input-gap);

  /* A resolved slot, not a state name — the one property assignment below
     reads this, and every state rule below only ever remaps it. */
  background-color: var(--usewc-color-input-background);
}

button:hover {
  --usewc-color-input-background: var(--usewc-color-input-background-hover);
}

button:focus-visible {
  outline: var(--usewc-size-focus-ring) var(--usewc-effect-focus-ring-style) var(--usewc-color-focus-ring);
  outline-offset: var(--usewc-space-input-focus-ring);
}

use-caret::part(icon-default) {
  color: var(--usewc-color-input-trigger-static);
}
```

Because `:hover` only ever reassigns the `--usewc-color-input-background` slot instead of setting `background-color` directly, the rule doubles as the reset point for `use-theme-escape` — reverting the single property-assigning rule reverts every state along with it, with nothing left over to unwind separately per state.

##### Token Categories

- `color`
- `size`
- `space`
- `font`
- `effect`
- `transition`

##### Component Categories

- `input` - anything that can hold a value
- `selector` - an input that toggles between two or three states (on / off, true / false, checked / unchecked / mixed)
  - `checkbox` - a selector that toggles between checked and unchecked
  - `radio` - a selector that toggles between checked and unchecked, but only one can be checked at a time
  - `switch` - a selector that toggles between checked and unchecked
- `action` - a button or link that triggers an action
  - `button` - a button that triggers an action
  - `link` - a link that triggers an action

##### Parts

- `root` - the root element of the component
- `trigger` - the popover indicator icon for the input
- `segment` - a piece of the whole value for the input
- `indicator` - the indicator for the selected state

##### Properties

- `background`
- `border`
- `text`
- `focus-ring`
- `padding`
- `gap`
- `shadow`

##### Property modifiers

- `inline`
- `block`
- `inset`
- `outset`

- `static`

##### Derivation knobs

Some components (currently `button`) compute their hover/active/border colors
from a single fill with `oklch(from …)` instead of naming every state
explicitly. The knobs behind that derivation follow the same
`--usewc-effect-<component>-<variant>-<name>` shape as any other effect token:

- `shift` - which direction interaction moves lightness (`-1` darkens, `1`
  lightens — dark-mode surfaces flip this)
- `hover-step` / `active-step` - how far hover/active move the fill's lightness
- `border-direction` - which direction the border sits relative to its own
  face (`-1` darker, `1` lighter)
- `border-step` / `border-step-hover` - how far the border moves from the face

A component that derives its states this way still keeps a plain,
overridable token for every state name (e.g.
`--usewc-color-button-base-background-hover`) — the knobs only describe how
that value's default is computed, not a replacement for the name.
