use-layout is a configurable flex-container primitive — like use-field, it's styled by tag name but isn't a registered custom element, and needs the design-system stylesheet loaded. Attributes drive the flex container: direction (column default, or row), align, justify, gap (a named scale, xsmall…super), wrap, and inline.

By default use-layout doesn't touch its children. Give a direct child use-layout the fill attribute and that child grows to consume the remaining space while every other child is pinned so it can't shrink. fill is read only on a use-layout, and only as a direct child, so an <svg fill="…"> or an author's own fill attribute is never picked up by accident.

Four variant classes name what the container is, and style its semantic <header>/<main>/<footer> regions to match: page for an app frame, prose for a document, message for a chat or comment, and card for a panel. Each selector is compound (use-layout.page, never a bare .page) so these common words can't collide with an author's own classes. direction="row" still overrides the column default on all of them.

Variants

All four regions are optional and any combination lays out correctly — <header> + <footer> is a confirm dialog, <header> + <main> a bare card, <main> alone a grouped chat message. Source order is canonical (figure, header, main, footer); a variant may re-position regions visually but never asks you to reorder markup.

A variant class sets only a density scale on itself — padding, gap, avatar size, which edges carry a hairline rule, and where the footer aligns. One generic set of region rules reads those properties, scoped in :where() so it adds no specificity: a header.tabbed of your own overrides it without a fight. The four densities are deliberately far apart, since a document and a card in a feed can't share one padding step and still read as themselves.

Wrap groups of items in <section>s to control the ends of a region: two or more <section> children switch it to space-between, dropping one group at each edge. A region with one section, or none, keeps its variant's default alignment.

Card

A unit in a grid or feed, at a compact density, and the only variant that paints chrome of its own (background, border, shadow); .outlined keeps the border and drops the shadow. Its header leads with an avatar and title group, and its footer collects actions at the inline-end edge. Add role/ARIA to the <use-layout> directly for real semantics — the tag carries none on purpose.

Inside a dialog or popover

A <dialog> and a [popover] are chrome only — background, border, shadow, backdrop, sizing. They carry no layout of their own, so nest a use-layout variant inside to arrange them. That keeps the overlay element's UA-controlled display alone and lets one dialog host any variant. Use a plain variant rather than .card there, since the overlay already paints its own surface.
